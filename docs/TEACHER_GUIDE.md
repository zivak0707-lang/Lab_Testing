## Швидкий старт

1. [Завантажте `Lab_Testing.exe`](https://github.com/zivak0707-lang/Lab_Testing/releases/latest/download/Lab_Testing.exe)
   — останній випуск, ≈ 52 МБ, Windows 10/11 x64, встановлювати .NET не потрібно
   ([усі випуски](https://github.com/zivak0707-lang/Lab_Testing/releases/latest)).
2. Запустіть програму → посилання **«Режим викладача»** на стартовій сторінці → пароль
   (пароль викладача можна отримати в автора; після входу змініть його кнопкою «Змінити пароль…»).
3. **«Банк питань і ключ…»** → **«Зберегти банк для редагування…»** — отримаєте JSON вбудованого демонстраційного банку.
   Відредагуйте питання (формат — нижче), перевірте кнопкою **«Перевірити файл банку…»**.
4. **«Підготувати банк для учнів (questions.dat + ZIP)…»** → виберіть порожню теку. Програма створить
   `questions.dat` і архів **`Lab_Testing_для_учнів.zip`** (програма + банк).
5. **Роздайте учням саме цей ZIP**, а не посилання на завантаження програми. Без вашого `questions.dat` учні пройдуть вбудований
   демонстраційний банк, а їхні файли буде підписано загальним ключем — у таблиці ви побачите «⚠ Загальний ключ».
6. Учні надсилають вам файли `Результат_….json`. Відкрийте їх у режимі викладача (кнопки або перетягніть з Провідника)
   і за потреби експортуйте таблицю в Excel.

## Режим викладача

- **Таблиця результатів:** ПІБ, група, дата, час, бали за кожне питання, оцінка за 12-бальною шкалою, порушення,
  справжність файлу і примітка. Подвійний клік — подробиці з розбором і хронологією подій.
- **«Файл справжній»:** ✔ Справжній — підписано вашим ключем і не змінювалось; ⚠ Загальний ключ — учень проходив тест
  без вашого банку; ⚠ Інший ключ — ключа немає на цьому комп'ютері (інший банк або підробка); ✗ Змінено! — файл
  редагували (у «Примітці» — що саме не сходиться); ⚠ Пошкоджено — файл не прочитати.
- **Експорт у Excel:** книга `.xlsx` (аркуші «Результати», «Події», «Пояснення») або CSV.
- **Пароль:** «Змінити пароль…». Новий пароль зберігається на цьому комп'ютері (`%AppData%\Lab_Testing`).

## Банк питань: формат і всі п'ять типів

Банк — текстовий файл JSON у кодуванні UTF-8 (Блокнот Windows 10/11 так і зберігає). Рядки, що починаються з `//`, —
коментарі. Найпростіше почати з шаблону: **«Зберегти шаблон банку…»** — у ньому по одному питанню кожного типу
з поясненнями біля кожного поля. Помилки в банку програма пояснює українською: рядок, номер питання, поле і як виправити.

**Правила:** номери питань (`id`) не повторюються; у банку має бути хоча б одне питання кожного типу (у тесті —
по одному випадковому питанню кожного типу); картки в межах питання не повторюються.

**Спільні поля питання:** `id`, `type` (`Basket`, `Table`, `Categories`, `Gaps`, `Order`), `topic` — тема,
`title` — коротка назва для таблиць, `task` — текст завдання, `theory` — теорія (лише в «Навчанні»),
`hint` — підказка після невдалої перевірки (без готової відповіді), `explanation` — пояснення правильної відповіді.
`theory`, `hint` і `explanation` можна писати одним рядком або списком рядків з розміткою:
`## Заголовок`, `- пункт`, `1. пункт`, `**жирний**`, `` `код` `` і блок коду між рядками з трьох зворотних лапок.

**Налаштування** (`settings`): `controlTimeMinutes` — час контрольної (1–180 хв); `showReviewAfterControl` — чи бачить
учень розбір після контрольної (бали й оцінку видно завжди); `gradeMinPercent` — мінімальний відсоток для оцінок 1…12;
`integrity` — режим доброчесності (див. нижче).

### «Кошик» (`Basket`) — лишити потрібні картки, зайві прибрати в кошик
```json
{
  "id": 1, "type": "Basket", "topic": "Типи даних", "title": "Типи даних",
  "task": "Залиште на слайді лише назви типів даних C#. Зайві картки перетягніть у кошик.",
  "items": [
    { "text": "int", "keep": true },
    { "text": "string", "keep": true },
    { "text": "Console", "keep": false }
  ]
}
```
`keep: true` — картка лишається на слайді, `false` — її треба прибрати. Потрібні й зайві картки — обов'язково обидва види.

### «Таблиця відповідностей» (`Table`) — картку в клітинку навпроти опису
```json
{
  "id": 2, "type": "Table", "topic": "Оператори", "title": "Оператор → дія",
  "task": "Перетягніть оператор у клітинку навпроти його дії. Одна картка зайва.",
  "columns": ["Дія", "Оператор"],
  "rows": [
    { "left": "Додавання", "answer": "+" },
    { "left": "Множення", "answer": "*" }
  ],
  "extraCards": ["-"]
}
```

### «Номерки на категорії» (`Categories`) — кружечки з номерами на рядки категорій
```json
{
  "id": 3, "type": "Categories", "topic": "Значення та їх типи", "title": "Числа і текст",
  "task": "Перетягніть кружечки з номерами значень на рядки відповідних категорій.",
  "categories": ["Числа", "Текст"],
  "items": [
    { "text": "7", "category": "Числа" },
    { "text": "3.5", "category": "Числа" },
    { "text": "\"Привіт\"", "category": "Текст" }
  ]
}
```
`category` — одна з назв у `categories`. Лапки всередині тексту пишуть як `\"`.

### «Слова в пропуски» (`Gaps`) — слова з палітри в пропуски тексту
```json
{
  "id": 4, "type": "Gaps", "topic": "Цикли", "title": "Цикл for",
  "task": "Перетягніть слова в пропуски. Одне слово можна використати кілька разів.",
  "text": "Цикл {for} повторює дії. Щоб достроково вийти з циклу {for}, використовують {break}.",
  "extraWords": ["if"]
}
```
Пропуск — правильне слово у фігурних дужках; те саме слово може стояти в кількох пропусках (учень копіює його).

### «Порядок кроків» (`Order`) — розставити кроки
```json
{
  "id": 5, "type": "Order", "topic": "Алгоритми", "title": "Привітання",
  "task": "Розставте кроки програми в правильному порядку.",
  "steps": [
    "string name = Console.ReadLine();",
    "string text = \"Привіт, \" + name;",
    "Console.WriteLine(text);"
  ]
}
```
Кроки записують **у правильному порядку** (від 3 до 8) — у тесті вони перемішуються.

**Бали:** кожне питання — до 20 балів (разом 100), частково правильна відповідь отримує частину балів.

## Банк для учнів і ключ підпису

**«Підготувати банк для учнів»** шифрує банк у `questions.dat` разом із вашим **ключем підпису** і паролем режиму
викладача. Учень, у якого поруч із програмою лежить ваш `questions.dat`, отримує ваші питання, а його файл результату
підписується вашим ключем — у вашій таблиці він «✔ Справжній».

- Ключ створюється автоматично на комп'ютері, де ви готуєте банк (`%AppData%\Lab_Testing`).
- **«Зберегти копію ключа…»** — збережіть копію (`.labkey`) у надійне місце (не в теку, яку отримують учні — програма
  попередить). **«Відновити ключ з файлу…»** — на іншому комп'ютері або після перевстановлення Windows.
- Без ключа ви не зможете підтвердити справжність файлів, підписаних ним (буде «⚠ Інший ключ»).

**Чесно про захист.** Підпис захищає від редагування файлу в Блокноті: будь-яка зміна дає «✗ Змінено!».
Але програма відкрита: загальний ключ і ключ шифрування `questions.dat` є в коді, тож програміст, який розбере
програму, теоретично може дістати ваш ключ з `questions.dat`. Для шкільної контрольної цього достатньо,
для іспиту з високими ставками — ні. Вбудований демонстраційний банк і його відповіді є в репозиторії —
для справжньої контрольної готуйте власний банк.

## Режим доброчесності контрольної

Вмикається в банку питань, розділ `settings` → `integrity` (у шаблоні банку кожне поле пояснено):

| Поле | За замовчуванням | Що означає |
|---|---|---|
| `enabled` | `true` | Контрольна на весь екран, вихід з вікна тесту записується |
| `exitLimit` | `3` | Після скількох виходів з вікна контрольна завершується достроково; `0` — лише записувати |
| `shortExitSeconds` | `2` | Вихід, коротший за стільки секунд (сповіщення, антивірус), не рахується, але записується |
| `hideFromCapture` | `false` | Вікно тесту не видно на знімках і записах екрана |

**Якщо під час контрольної ви спілкуєтеся з учнями через Zoom, Google Meet чи месенджер — ставте `"exitLimit": 0`.**
Інакше учень, який перейде в Zoom, щоб відповісти вам, вичерпає ліміт виходів, і його контрольну буде завершено достроково.
З `0` виходи однаково записуються — ви побачите їх у таблиці.

**`hideFromCapture`** вмикайте, лише якщо демонстрації екрана не буде: із захистом Zoom/Meet покажуть чорне вікно замість тесту.

Що бачить учень: перед стартом — правила (що саме записується) і підтвердження «Я проходжу тест самостійно і чесно»;
під час контрольної — смугу з кількістю виходів; після кожного виходу — попередження.
Що бачите ви: стовпець «Порушення» (рядок з порушеннями — фіолетовий), подробиці з хронологією подій,
стовпці «Порушення» і «Завершення» та аркуш «Події» в Excel. Усе це — у підписаному файлі, змінити непомітно неможливо.

Програма нічого не блокує: Alt+Tab, Win, Ctrl+Alt+Del, Alt+F4 працюють як завжди, а вихід з вікна лише записується.

**Від чого режим НЕ захищає:** телефон чи другий пристрій, людина поруч, підказки на другому моніторі
(програма лише позначить «моніторів: 2»), віртуальна машина, фото екрана телефоном (його не зупинить і захист від знімків).
Офлайн-програма ускладнює нечесне проходження і дає вам повну картину, але не замінює нагляду.

## Повторні спроби і написання ПІБ

Номер спроби у стовпці «Спроба» рахує **ваша** програма — за відкритими вами файлами одного учня (за ПІБ і групою),
а не лічильник на комп'ютері учня: той легко обійти, видаливши `%AppData%\Lab_Testing` або пройшовши тест на іншому комп'ютері.
Повторна спроба — помаранчевим, а в «Примітці» пояснено, що помічено:

- «повторна спроба: 2-а з 3 цього учня» (серед файлів, відкритих у таблиці);
- «у файлі — спроба №1 (лічильник на ПК учня)» — лічильник учня не збігається з вашим;
- «латинські літери в ПІБ: «e» у «Пeтренко»» — латинські літери, схожі на українські; «ПІБ записано по-різному» — інший апостроф, регістр чи порядок слів;
- «такий самий ПІБ — у групі …», «схожий ПІБ: …» — підказки, перевірте самі;
- «копія файлу …» — той самий файл (можливо, змінений) відкрито ще раз; окремою спробою не рахується;
- «той самий номер спроби, що й у файлі …» — у двох різних учнів однаковий номер спроби: один файл, схоже, зроблено з чужого результату.

Під час порівняння ПІБ не важать: латинські літери, що виглядають як українські (i/і, a/а, e/е, o/о, c/с, p/р, x/х…),
різні апострофи (' ’ ʼ), регістр, зайві пробіли і порядок слів. А ввести ПІБ з латинськими літерами учень не може:
програма попросить писати кирилицею.

**Обмеження:**
- групуються лише файли, які ви відкрили: якщо учень здав одну «найкращу» спробу, пройдену на іншому комп'ютері,
  інших спроб ви не побачите;
- зовсім інше написання (помилка в прізвищі, інше ім'я) — це «інша людина»; «схожий ПІБ» — лише підказка;
- чуже ПІБ (учень пройшов за іншого) програма не розпізнає.

## Журнал діагностики

Програма веде журнал `%AppData%\Lab_Testing\log.txt` на комп'ютері, де її запускали: запуск програми, початок і кінець
контрольної, кожна подія режиму доброчесності, збереження файлу результату і помилки програми.
Особистих даних понад те, що вже є у файлі результату, там немає (шлях до профілю Windows прихований).
Якщо у спірній ситуації потрібні подробиці — попросіть учня надіслати цей файл.

Журнал лежить на комп'ютері учня, і його можна видалити чи змінити, тому доказом він не є.
Доказ — підписаний файл результату.

## Якщо програма дала збій

Якщо під час контрольної сталася непередбачена помилка програми, контрольна завершується, а відповіді, які учень
встиг дати, одразу зберігаються у файл результату. Режим «на весь екран» знімається, учень бачить зрозуміле повідомлення,
де лежить файл. У таблиці в стовпці «Завершення» буде «через помилку програми», а подробиці помилки — у журналі учня.

Якщо процес програми примусово закрили (Диспетчер задач → «Зняти завдання») або вимкнулося живлення,
файл результату не збережеться — це обмеження будь-якої програми.

## Сценарій передачі: автор готує банк для вчителя

Коли банк для учнів готує не сам учитель, а інша людина (наприклад, автор програми), ключ підпису і пароль
створюються на комп'ютері автора. Щоб після передачі доступ до результатів мав **лише вчитель**:

**Автор:**
1. Запускає опублікований `Lab_Testing.exe`, входить у режим викладача, змінює пароль на новий (його отримає вчитель).
2. «Банк питань і ключ…» → вибирає банк з файлу JSON → «Підготувати банк для учнів…» у порожню теку.
3. «Зберегти копію ключа…» → файл `.labkey` (в окрему теку, не туди, де ZIP для учнів).
4. Передає вчителю: архів `Lab_Testing_для_учнів.zip`, файл ключа `.labkey` і пароль (пароль — окремим каналом,
   наприклад, телефоном).
5. Після того як учитель підтвердив, що все працює, **повністю видаляє в себе**:
   - теку `%AppData%\Lab_Testing` (ключ, змінений пароль, резервні копії результатів, журнал): Win+R →
     `%AppData%` → видалити теку `Lab_Testing`;
   - файл `.labkey`, `questions.dat`, ZIP і JSON банку — разом із копіями в «Завантаженнях», месенджерах і хмарі;
   - очищує кошик.

**Учитель:**
1. Розпаковує ZIP у свою теку і запускає `Lab_Testing.exe` (поруч лежить `questions.dat`).
2. Режим викладача → пароль від автора → «Змінити пароль…» на власний.
3. «Банк питань і ключ…» → «Відновити ключ з файлу…» → файл `.labkey`. Номер ключа у вікні має збігатися з тим,
   що повідомив автор.
4. Перевірка: проходить контрольну як «учень», відкриває свій файл результату в режимі викладача — має бути
   «✔ Справжній». Після цього зберігає `.labkey` у надійне місце і роздає учням ZIP.
